# 功能档案：购买廉价鱼食

## 功能定位

`BuyFishFoodTask` 是可独立运行、也可作为日常收尾可选子任务或供后续海星自动补粮流程调用的金币购买模块。当前仅支持单价 400 金币、每袋 30 粒的“廉价鱼食”，不涉及贝币、钻石或现实付费商品。

廉价鱼食的资源属性及实机测试授权见 `docs/game-knowledge.md`：在视觉门禁确认类别后，允许为跑通完整流程进行充分、重复的购买测试。

## Start Contract

任务按最深阶段优先识别，支持从以下页面启动：

1. 廉价鱼食详情页；
2. 鱼食商品列表；
3. “选择喂食”弹窗；
4. 主鱼缸。

无法确认上述任一页面时直接进入 `BuyFishFoodAbort`，不会使用固定坐标猜测当前状态。

## 流程

```text
BuyFishFoodTask
  -> StartRouter
  -> 识别鱼缸后模板点击鱼食袋入口
  -> OCR 确认“选择喂食”
  -> 模板点击蓝色加号
  -> OCR 确认商品列表
  -> OCR 查找并点击“廉价鱼食”
     -> 当前屏未找到时，在已确认的商品区域内每次短滑 100px，最多 12 次
  -> 同时确认“廉价鱼食” + 单价 400 + 加号模板 + “购买”按钮
  -> OCR 读取当前数量（数量框使用整块识别，并兼容单独“1”被识别为“」”）；大数量使用可取消的 Maa 原生分段长按
  -> 接近目标后单击补齐，并在每次动作前后检查停止状态
  -> OCR 点击“购买”一次
  -> 确认自动返回商品列表
  -> OCR 点击“返回”一次
  -> 模板确认回到主鱼缸
```

## 防误触边界

- 鱼食袋入口、蓝色加号、数量加号均点击当帧模板匹配框中心，不设置固定点击 `target`。
- 廉价鱼食、购买、返回均点击当帧 OCR 识别框中心。
- 每次增加数量前重新确认详情页和加号；不读取背包 `9999+`，也不依赖金币差值判断结果。
- 长按以 Maa 原生 `LongPress` 执行并分段 OCR 数量，用户停止任务时通过 `Tasker.stopping/running` 在下一动作前熔断。
- 只有商品列表的滑动轨迹使用固定坐标 `[640,580] → [640,480]`、时长 500ms；每次滑动前须确认“返回”和当前屏商品文字，最多滑动 12 次。与旧版 180px/400ms 相比步幅更短、速度更慢，每步后重新截图找“廉价鱼食”。
- 任一关键门禁失败即返回 `False`，宁可停在当前安全页面，也不盲点返回或购买其他商品。
- 详情页数量框只识别白底数字区域 `[892, 345, 125, 92]`，避免把右侧单价 `400` 读进购买数量。
- 商品列表身份不使用泛化的“鱼食”二字，避免详情页说明文字把详情页误判成商品列表；除“成长豆/糖”外，也识别列表中的“雪花鱼食/粉光鱼食/珀光鱼食”等明确商品名。若当前屏只剩“廉价鱼食”卡片，仍可在“返回”门禁下点击该卡片，但点击后必须同时确认详情标题和单价 400。若已同时识别到“廉价鱼食”和单价 400，直接进入购买，不再点击列表。

## 参数与复用

- UI 参数：`购买廉价鱼食袋数`，范围 1 到 9999，默认 1；既有购买动作按每批最多 999 袋拆分，用户可按需增大。
- Pipeline 参数：`BuyCheapFishFoodAction.custom_action_param.bags`。
- 日常收尾勾选“购买鱼食”后通过 case 的 `option` 展开同一个 `购买廉价鱼食袋数` 输入组，统一覆盖详情页直启和商品列表进入两个购买节点，避免 checkbox 中引用未绑定的 `{袋数}`。
- 调度器读取 `DailyRoutineEnableBuyFishFood`，安排在浪漫满屋后、鱼宝乐园前。两条购买成功路径均经过 `BuyFishFoodDone` 再次确认主鱼缸，由 `DailyRoutineSubtaskDoneAction` 写入完成状态；日常继续队列，独立任务正常结束。失败进入 `BuyFishFoodAbort` / `StopTask`，不伪报完成或推进队列。
- 后续海星大功能可复用 `BuyFishFoodTask`，或覆盖 `BuyFishFoodStartAtDetail` 与 `BuyFishFoodPurchaseOnDetail` 的 `bags` 参数后进入该模块。
