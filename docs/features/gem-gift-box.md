# 宝石礼盒兑换功能 (`GemGiftBoxTask`)

## 功能目标

从主鱼缸右下角宝箱进入宝石礼盒兑换页，依次处理 16、21、26、31、36、41、46 级七张配方卡片。每张卡片本日最多兑换至 `10/10`，完成后返回主鱼缸。

本功能使用用户提供的截图、模板和 ROI 实现；本轮仅做代码级验证，不代表 MFA 实机识别已经通过。

## 启动与导航契约

```text
GemGiftBoxTask
  ├─ 已在兑换列表 -> GemGiftBoxRun
  ├─ 已打开宝箱菜单 -> 识别点击宝石礼盒兑换入口 -> GemGiftBoxRun
  ├─ 主鱼缸 -> 识别点击右下角宝箱 -> 识别点击兑换入口 -> GemGiftBoxRun
  └─ 已停在兑换弹窗 -> 安全停止（无法确认弹窗所属配方，禁止猜测后重复兑换）
```

- 右下角宝箱：`右下角_宝箱.png`，ROI `[1120,562,141,141]`。
- 兑换入口：`宝石礼盒兑换入口.png`，ROI `[828,575,132,121]`。
- 兑换列表页面门禁：OCR 稳定子串 `兑换鱼配方数`，兼容实机完整文本 `宝石兑换鱼配方数：21`。
- 进入列表后先检查 `16级配方`，基准 ROI `[55,196,108,41]`；未命中时只在列表页面门禁仍成立的前提下向页面顶部回滚，直到确认首屏。

## 七配方防重与防漏规则

固定处理顺序为：

```text
16 -> 21 -> 26 -> 31 -> 36 -> 41 -> 46
```

每一项都先 OCR 定位配方等级，再在同一张卡片内检查状态：

1. 识别到 `今日已兑换10/10`：该配方已经完成，跳过，不点击仍可能存在的 OK。
2. 尚未达到 `10/10`：按配方所在左右列和纵向位置推导同卡片 OK 搜索区，再匹配 `宝石礼盒_可兑换.png`；OK 只作为可兑换状态门禁，不直接点击。
3. 尚未完成但没有识别到对应 OK：安全停止，不把该配方静默记作完成，避免漏兑。
4. 兑换成功返回列表后，必须再次识别同卡片 `今日已兑换10/10`；未确认则停止且不重复提交。

用户提供的基准映射为：配方文字 ROI `[55,196,108,41]` 对应同卡片 OK ROI `[587,195,47,35]`。两个矩形中心分别为 `(109,216.5)` 和 `(610.5,212.5)`，卡片点击点取二者中点并按常规四舍五入为 `(360,215)`。运行时使用实际识别框动态计算同一卡片的中点，横向仍锁定卡片右上角，纵向根据当前 OCR 配方位置小范围跟随，以兼容列表滚动错位。

## 单卡兑换流程

```text
配方未满 10/10
  -> 识别同卡片 OK
  -> 点击配方文字与 OK 的中点（卡片主体）
  -> 模板确认兑换弹窗
  -> 模板识别加号并点击 9 次
  -> OCR 精确识别并点击“兑换”
  -> OCR 精确识别并点击“确定”
  -> 返回列表并复核该配方 10/10
```

- 兑换弹窗：`宝石礼盒_兑换识别.png`，ROI `[771,229,200,180]`。
- 加号：`宝石礼盒兑换_点击.png`，ROI `[878,336,134,132]`；识别一次后固定点击 9 次，超过当前可增加上限时按钮不再增加数量，不执行其他坐标兜底。
- 兑换按钮：OCR `^兑换$`，ROI `[789,486,169,131]`，避免误点“今日已兑换”计数文字。
- 确定按钮：OCR `^确定$`，ROI `[557,568,178,135]`。

## 结束契约

七个配方均已新兑换至 `10/10` 或在开始时确认已经 `10/10` 后，OCR 点击左上角通用返回；只有 `主界面特征.png` 命中后任务才算完成。任何页面门禁、弹窗、按钮或结果复核失败都会进入 `GemGiftBoxAbort` 安全停止。

## 代码级验证

`python dev/test_gem_gift_box.py` 覆盖：

- 用户提供模板和 ROI；
- 实机页面标题中的 `鱼` 字门禁，以及基准卡片中点 `(360,215)`；
- 三入口拓扑与退出主鱼缸验证链；
- 七个配方身份顺序；
- 已完成卡片即使 OK 仍存在也不会重复兑换；
- 未完成卡片固定执行 9 次加号并在确认后更新到 `10/10`；
- 下半页滚动查找 36、41、46 级配方。
