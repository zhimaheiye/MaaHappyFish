# 多鱼缸巡检

## 目标与边界

`PatrolTask` 是独立于“收鱼产物”的长时间巡检任务：

1. 依次进入鱼缸 1、2、3，收取当前画面中的金币产物；
2. 从第三缸进入鱼缸管理页，并只进入一次通用海星页面；
3. 在通用海星页面依次点击顶部“萌海星 / 乖海星 / 亮海星”标签，为三只海星补充鱼食；
4. 正常完整一轮返回第三缸；若从管理页断点启动，则返回进入管理页前的原鱼缸。验证任一主鱼缸后等待用户配置的巡检间隔，再开始下一轮。

本版本还提供两个默认关闭的每小时子任务：魔力召唤、宝石融合。用户可分别勾选；它们只在一轮多鱼缸收宝与海星喂食结束后的等待阶段运行。

鱼缸 1、2 的海星投放当前限定为廉价鱼食；鱼缸 3 是深海鱼缸，使用弹窗第一格专用鱼食且不触发购买。资源属性及实机测试授权边界见 `docs/game-knowledge.md`。

## 与“收鱼产物”的区别

- `CollectFishTask`：面向当前单个鱼缸，可持续收宝或按占空比激活，并独立定时喂当前缸海星。
- `PatrolTask`：每轮固定巡检 1/2/3 三个鱼缸；收宝结束后只进入一次通用海星页面，再通过顶部标签依次喂食。
- 两个任务入口、计时器和 Pipeline 相互独立，避免改变已有单缸挂机行为。

## 一轮状态机

```text
StartRouter
  -> 归一到鱼缸 1
  -> 收宝 1（SHAKE 模式先摇晃扫底，再用图像识别复查；连续 30 秒无目标才结束，每次命中后重新计时）
  -> 识别并切换鱼缸 2 -> 验证 -> 收宝 2
  -> 识别并切换鱼缸 3 -> 验证 -> 收宝 3
  -> 识别扳手 -> 验证鱼缸管理页 -> OCR 点击任一海星进入通用海星页面
  -> OCR 点击“萌海星”顶部标签 -> 验证正文标题 -> 按实际喂食弹窗选择鱼食
  -> OCR 点击“乖海星”顶部标签 -> 验证正文标题 -> 按实际喂食弹窗选择鱼食
  -> OCR 点击“亮海星”顶部标签 -> 验证正文标题 -> 按实际喂食弹窗选择鱼食
  -> OCR 点击通用返回 -> 验证鱼缸管理页 -> 再返回并验证任一已知主鱼缸
  -> WaitLoop（主巡检 > 魔力召唤 > 宝石融合；全局弹窗仍可抢占）
```

收宝识别范围为 `[0, 100, 1280, 560]`，覆盖横向水体但排除顶部资源栏。金币模板命中后点击识别结果中心，不设固定坐标；每次点击后立即在鱼缸底部安全范围 `[201,630,826,66]` 内执行 `(221,663) -> (1007,663)`，再沿原轨迹反向滑回 `(1007,663) -> (221,663)`，主动收取空中产物后再继续识别。每个鱼缸最终都使用硬编码的 30 秒“无产物窗口”：IMAGE 模式直接进入该窗口；SHAKE 模式完成五轮摇晃、逐轮双向扫底和最终双向扫底后，也必须进入同一套图像识别复查，不能直接切缸。窗口内一旦命中并点击产物就重新开始 30 秒计时；连续 30 秒没有识别到产物（包括一开始就没有、或已经全部收完）时视为该缸正常完成并切换下一缸，不记录为任务错误。该时长不暴露为用户参数。

收宝期间误触游动海星处理：若点击产物时与游动的萌海星碰撞意外进入海星宠物页（`萌海星(宠物)`），由各鱼缸收集与复查节点优先以顶部专属海星标签门禁（ROI `[80, 70, 800, 100]`，OCR `[萌乖亮]海星`）识别该页面，并在 `[1, 0, 189, 119]` OCR 点击左上角“返回”；返回后必须使用各自主页面编号模板（`patrol/鱼缸X_主页面编号.png`，ROI `[40, 32, 45, 48]`，阈值 0.85）确认已经回到原鱼缸，再重新进入该缸的 30 秒观察窗口，重置计时并继续收宝。在切缸/进入管理页前增加轻量状态保护路由（`PatrolPreSwitchCheckTank1/2`、`PatrolPreManagementCheckTank3`），若处于海星宠物页则优先恢复，若未知页面则安全停止，杜绝在非鱼缸页面盲找编号或盲点展开按钮导致的 `error handling loop detected`。

巡检点击或底部滑动误触贝壳时按真实层级恢复：第一层入口页先用 `开贝壳_误触识别.png`（ROI `[498,80,280,191]`）确认，再在 `[1,0,189,119]` OCR 点击左上角“返回”，通过 `[JumpBack]PatrolShellEntryMisTouchPopup` 继续原节点；若已进入第二层大章鱼主页，则仍先用 `开贝壳_识别.png`（ROI `[37,68,226,142]`）确认页面本体，再用 `贝壳页面_返回.png`（ROI `[0,0,250,150]`）点击真实返回按钮。两层门禁互不复用，也不使用 `活动页面_退出.png`。产物点击到滑动仍保持不可拆开的原子链，滑动完成后立即检查两层误触状态。

## 计时语义

- 可配置项：`多鱼缸巡检间隔`，默认 30 分钟。
- 任务启动先立即执行一轮。
- 首轮结束后才初始化等待计时，避免首轮结束时立即重复执行。
- 等待期间每秒回到调度循环一次，因此意外活动页面、跨零点签到和特惠礼包全局弹窗仍能被处理。
- 魔力召唤和宝石融合使用彼此独立的 3600 秒计时器；勾选后在首轮主巡检完成时立即检查一次，此后每小时检查。
- 若多个任务同时到期，固定优先级为：多鱼缸收宝与喂食 > 魔力召唤 > 宝石融合。

## 日志与等待心跳

- 巡检的关键动作和识别结果通过 Pipeline `focus` 写入 MFA 日志面板，同时进入客户端日志文件。日志按“当前对象 -> 执行动作 -> 验证结果/下一步”表述，不要求用户从内部节点名判断进度。
- 三缸收宝只打印：进入哪个鱼缸；SHAKE 模式完成摇晃扫底并转入图像复查；以及连续 30 秒无产物后完成该缸并切换/进入管理页。单个产物命中、点击、底部滑动和无产物窗口重置不逐次播报，避免长时间巡检刷屏。
- 三只海星分别打印：点击并确认哪个标签、打开选择鱼食、识别为普通或深海专用鱼食、执行投放、弹窗关闭且正文仍为当前海星时确认投放成功。
- 每轮完成后打印下一次主巡检的绝对时间；静止等待期间每 5 分钟打印一次心跳和剩余秒数。屏幕不动但心跳继续出现表示正常等待；门禁失败会打印明确的安全停止日志，不会伪装成等待。
- 魔力召唤区分“高级召唤已启动”“上一轮结果已揭晓并领取”“检测到正在召唤，本次未重复召唤”；宝石融合区分“上一轮结果已放入仓库并再次合成”“已启动下一轮”“检测到正在融合，本次未重复合成”。两项完成后都打印已返回主鱼缸并继续调度。
- 等待间隔从每轮主巡检真正完成时重新计时，不把执行本轮巡检所花的时间计入下一轮等待。

## 通用海星页面与深海鱼食兼容

- 从任一鱼缸的管理页进入海星后，实际都会进入同一个通用海星页面。流程只进入一次，随后在覆盖三个标签的顶部 ROI `[80, 70, 800, 100]` 依次 OCR 点击“萌海星 / 乖海星 / 亮海星”，并在正文 ROI `[330, 140, 420, 130]` 用对应完整名称确认切换成功。禁止为了喂下一只海星退出页面、切换鱼缸后再重新进入。
- 鱼缸与海星的对应关系不硬编码。当前鱼缸 3 恰好对应第二个“乖海星”，但以后对应关系可能变化；每只海星打开喂食弹窗后，都先按弹窗的真实内容路由：匹配到 `普通鱼食袋.png` 就点击廉价鱼食，匹配到深海加号才进入专用鱼食分支。
- 在三种鱼食布局的选择喂食弹窗中，用用户指定范围 `[450, 151, 199, 191]` 匹配 `海星_加号.png`，以此确认已经进入正确的深海鱼食弹窗。
- 通过门禁后点击与该加号对应的专用鱼食范围 `[649, 204, 57, 91]`。点击区从加号 ROI 的右边界开始，与门禁区域不重叠；若加号门禁未通过，不点击鱼食并安全返回。
- 点击后先在 `[700, 90, 240, 150]` OCR 检查“选择喂食”：若弹窗仍在则安全停止；若弹窗已关闭，则必须重新识别当前海星正文标题后才能切换下一个标签。不能把候选节点的 `on_error` 当作“未识别即成功”分支。
- 不购买深海专用鱼食。三只海星共享同一深海候选，因为对应关系可能变化；普通鱼食优先，只有普通鱼食未命中且新加号门禁通过时才点击上述专用鱼食区域。

## 每小时可选子任务

### 魔力召唤

```text
右下角宝箱 [1120,562,141,141]
  -> 魔力召唤入口 [415,593,173,124]
  -> OCR 标题 [468,0,345,146]
  -> 上一轮刚结束：OCR 点击“揭晓” [827,501,210,145] -> OCR 点击“确定” [538,399,202,142] -> 接空闲启动流程
  -> 有高级召唤黄色按钮 [811,495,232,148]：点击 -> 绿色勾选 [751,404,153,150] -> 返回
  -> 无黄色按钮：视为正在召唤 -> 直接返回，不报错
```

标题 OCR 同时兼容整体“魔力召唤”和分词后的“魔力”“召唤”。页面状态按并列分支处理：高级召唤确认弹窗优先，其次是上一轮结束的“揭晓”，再其次是空闲状态的高级召唤按钮；以上均未命中但仍在召唤页时，视为正在召唤并直接返回。揭晓后必须在用户给定 ROI 内 OCR 命中“确定”才点击，随后接回既有空闲启动流程。高级召唤会消耗稀缺资源且十小时才能再次执行，确认前必须再次核对页面门禁。

### 宝石融合

```text
右下角宝箱 [1120,562,141,141]
  -> 宝石融合入口 [632,591,135,128]
  -> 优先用 宝石融合_产物识别.png [172,128,230,212] 判断上一轮产物弹窗
       -> 命中后 OCR 点击“放入仓库” [565,537,152,42]
       -> 重新验证宝石融合页面，再继续本轮合成
  -> 验证宝石融合页面 [549,0,178,242]
  -> 有“合成” [825,556,178,140]：点击后返回
  -> 第一次返回后先验证主鱼缸
       -> 已回到任一主鱼缸：继续调度
       -> 优先检测“放入仓库”：说明第一次返回关闭了外层临时弹窗并暴露出上一轮奖励弹窗，直接点击“放入仓库”并继续下一轮合成
       -> 无奖励且仍识别到宝石融合页面：说明第一次点击只关闭了普通临时弹窗，再识别点击“返回”并复验主鱼缸
```

结果弹窗、空闲可合成和正在融合三种路由都不会使用识别失败后的盲点坐标。上一轮产物优先通过 OCR 识别点击“放入仓库”（ROI `[565, 537, 152, 42]`），入库后重新确认融合页再进行本轮合成。兼容返回弹窗时也不盲点屏幕：第一次返回后若未回到主鱼缸，Router 会优先检测是否暴露出上一轮奖励的【放入仓库】弹窗并接入既有合成闭环；只有在没有奖励弹窗且重新命中 `宝石融合页面.png` 时，才允许第二次 OCR 识别并点击“返回”；若既不是主鱼缸、亦无奖励弹窗、也不是融合页面则安全停止。

## Start Contract

支持从以下真实页面启动或恢复：

- 鱼缸 1、2、3 主页面：识别左上角当前鱼缸编号；若不是第一缸，先通过展开选择器归一到第一缸。
- 已展开的鱼缸选择器：识别并点击选择器中的第一缸。
- 鱼缸管理列表页：按 deepest-first 直接进入通用海星页面，不强制退回主鱼缸。退出管理页后接受真实返回的 1/2/3 缸，下一轮再归一到第一缸。
- 通用海星页面：从“萌海星”开始重新执行三标签喂食流程。若任务从“选择喂食”弹窗启动，由于无法可靠知道上一步所属标签，安全停止而不盲点。

其他未知页面不做固定坐标兜底，直接 `StopTask` 并输出门禁失败日志。

### 模板取证事故与约束

初版误把“展开选择器里的小号鱼缸编号”同时用于识别“主页面左上角的大号当前鱼缸编号”。两者肉眼图案相似，但真实像素尺寸不同，导致主页面启动识别 8/8 次失败。改用完整主页面编号牌后又通过交叉实机检查发现：三张图共享区域过多，错误编号也可能超过低阈值。最终模板进一步紧裁到数字本体，并用三个主页面互作负样本。以后必须遵守：点击或识别哪个页面状态下的控件，就从该页面状态单独截图；主页面当前缸标识、展开选择器入口、管理页选中态不得互相代用。每类模板接入前都要在其真实页面用 Maa benchmark_node 验证，并对同类相似控件做交叉负样本验证。

### MaaMCP 长任务测试注意

`PatrolTask` 设计为进入 `PatrolWaitLoop` 后长期运行，不应把 maa-mcp 的 `run_pipeline` 当作会自然结束的短测试。2026-09-08 的调试中，工具调用超时后 `stop_pipeline` 返回过 `tasker_stopped=false`，旧循环仍在日志中继续运行；当次已核对 PID 并终止 MaaMCP 进程完成清理。后续实机调试必须采用有界节点/阶段测试，或在外部明确观察到目标阶段后立即停止，并核对停止结果，不能只看调用返回就假定后台任务已结束。
