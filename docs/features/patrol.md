## 目标与边界

2026-10-02 新增好友摸宝重启报告已处理：巡检插入的十点/二十二点好友任务及十二点日常共用本机持久化日期；重建 Agent 后仍保持当天各档已尝试状态，返回栈不恢复，实际页面重新识别。原巡检间隔与每小时魔力召唤/宝石融合不变。日期是自动启动去重，不是完成计数，详见 [daily-routine.md](daily-routine.md)。跨进程代码级验证通过，未做实机测试。

`PatrolTask` 是独立于“收鱼产物”的长时间巡检任务：

1. 依次进入鱼缸 1、2、3，收取当前画面中的金币产物；
2. 从第三缸进入鱼缸管理页，并只进入一次通用海星页面；
3. 在通用海星页面依次点击顶部“萌海星 / 乖海星 / 亮海星”标签，为三只海星补充鱼食；
4. 正常完整一轮返回第三缸；若从管理页断点启动，则返回进入管理页前的原鱼缸。验证任一主鱼缸后等待用户配置的巡检间隔，再开始下一轮。

本版本还提供两个默认关闭的每小时子任务：魔力召唤、宝石融合。用户可分别勾选；它们只在一轮多鱼缸收宝与海星喂食结束后的等待阶段运行。

`DailyRoutineTask` 也可分别勾选这两项，在日常队列中各检查一次并复用本任务的页面门禁与结果处理，不进入这里的每小时等待/计时器；日常模式完成后须先识别鱼缸编号再推进下一个子任务。高级召唤的原有确认门禁不变。该接入已做代码级验证，尚未做 MFA/模拟器验证。

三只海星先自动投放廉价、普通、高级鱼食。默认排序从加号右边第一格开始认廉价，认不到再认右边第二格的普通，再认加号正下方的高级。三种都没有时，再认深海缸加号右边第一格的粉光鱼食字块。字块不在第一格，或另外两袋深海鱼食，都不点，任务失败。资源边界见 `docs/game-knowledge.md`。

## 与“收鱼产物”的区别

- `CollectFishTask`：面向当前单个鱼缸，可持续收宝或按占空比激活，并独立定时喂当前缸海星。
- `PatrolTask`：每轮固定巡检 1/2/3 三个鱼缸；收宝结束后只进入一次通用海星页面，再通过顶部标签依次喂食。
- 两个任务入口、计时器和 Pipeline 相互独立，避免改变已有单缸挂机行为。

## 一轮状态机

```text
StartRouter
  -> 归一到鱼缸 1
  -> 收宝 1（SHAKE 模式先摇晃扫底，再用图像识别复查；连续 30 秒无目标才结束，每次命中后重新计时）
  -> 识别并切换鱼缸 2 -> 验证 -> 收宝 2
  -> 识别并切换鱼缸 3 -> 验证 -> 收宝 3
  -> 识别扳手 -> 验证鱼缸管理页 -> OCR 点击任一海星进入通用海星页面
  -> OCR 点击“萌海星”顶部标签 -> 验证正文标题 -> 按实际喂食弹窗选择鱼食
  -> OCR 点击“乖海星”顶部标签 -> 验证正文标题 -> 按实际喂食弹窗选择鱼食
  -> OCR 点击“亮海星”顶部标签 -> 验证正文标题 -> 按实际喂食弹窗选择鱼食
  -> OCR 点击通用返回 -> 验证鱼缸管理页 -> 再返回并验证任一已知主鱼缸
  -> WaitLoop（主巡检 > 魔力召唤 > 宝石融合；全局弹窗仍可抢占）
```

收宝识别范围为 `[428,126,679,360]`，与单缸收鱼相同，排除顶部资源栏及左右图标列。必须同帧确认当前缸编号与范围内金币，点击金币命中框中心；每次点击后先复核本缸门禁，再在底部安全范围 `[201,630,826,66]` 内执行 `(221,663) -> (1007,663)`，反向滑动前也复核本缸。每个鱼缸最终都使用硬编码的 30 秒“无产物窗口”：IMAGE 模式直接进入该窗口；SHAKE 模式完成五轮摇晃、逐轮双向扫底和最终双向扫底后，也必须进入同一套图像识别复查，不能直接切缸。窗口内一旦命中并点击产物就重新开始 30 秒计时；连续 30 秒没有识别到产物时正常切缸，范围外产物由既有摇晃/扫底收取，不扩大气泡点击区域。该时长不暴露为用户参数。

收宝期间误触游动海星处理：若点击产物时与游动的萌海星碰撞意外进入海星宠物页（`萌海星(宠物)`），由各鱼缸收集与复查节点优先以顶部专属海星标签门禁（ROI `[80, 70, 800, 100]`，OCR `[萌乖亮]海星`）识别该页面，并在 `[1, 0, 189, 119]` OCR 点击左上角“返回”；返回后必须使用各自主页面编号模板（`patrol/鱼缸X_主页面编号.png`，ROI `[40, 32, 45, 48]`，阈值 0.85）确认已经回到原鱼缸，再重新进入该缸的 30 秒观察窗口，重置计时并继续收宝。在切缸/进入管理页前增加轻量状态保护路由（`PatrolPreSwitchCheckTank1/2`、`PatrolPreManagementCheckTank3`），若处于海星宠物页则优先恢复，若未知页面则安全停止，杜绝在非鱼缸页面盲找编号或盲点展开按钮导致的 `error handling loop detected`。

巡检点击或底部滑动误触贝壳时按真实层级恢复：第一层入口页先用 `开贝壳_误触识别.png`（ROI `[498,80,280,191]`）确认，再在 `[1,0,189,119]` OCR 点击左上角“返回”，通过 `[JumpBack]PatrolShellEntryMisTouchPopup` 继续原节点；若已进入第二层大章鱼主页，则仍先用 `开贝壳_识别.png`（ROI `[37,68,226,142]`）确认页面本体，再用 `贝壳页面_返回.png`（ROI `[0,0,250,150]`）点击真实返回按钮。两层门禁互不复用，也不使用 `活动页面_退出.png`。2026-10-02 起气泡点击到双向扫底之间各加本缸门禁，失配转回观察窗口按真实页面处理，不能以“原子链”为由在其它页面继续滑动。

## 计时语义

- 可配置项：`多鱼缸巡检间隔`，默认 30 分钟。
- 任务启动先立即执行一轮。
- 首轮结束后才初始化等待计时，避免首轮结束时立即重复执行。
- 等待期间每秒回到调度循环一次，因此意外活动页面、跨零点签到和特惠礼包全局弹窗仍能被处理。
- 魔力召唤和宝石融合使用彼此独立的 3600 秒计时器；勾选后在首轮主巡检完成时立即检查一次，此后每小时检查。
- 若多个任务同时到期，固定优先级为：多鱼缸收宝与喂食 > 魔力召唤 > 宝石融合。

### MaaMCP 长任务测试注意

`PatrolTask` 设计为进入 `PatrolWaitLoop` 后长期运行，不应把 maa-mcp 的 `run_pipeline` 当作会自然结束的短测试。2026-09-08 的调试中，工具调用超时后 `stop_pipeline` 返回过 `tasker_stopped=false`，旧循环仍在日志中继续运行；当次已核对 PID 并终止 MaaMCP 进程完成清理。后续实机调试必须采用有界节点/阶段测试，或在外部明确观察到目标阶段后立即停止，并核对停止结果，不能只看调用返回就假定后台任务已结束。
