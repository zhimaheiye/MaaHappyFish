## 使用与 Start Contract

- 在开发客户端添加「购物狂欢季合成」，先打开活动棋盘，再开始任务。默认只合成现有棋子；可选择「使用已有体力生成并合成」，每次最多生成 200 枚（保险箱与体力生成合计）。该模式在无可合成对时优先使用 5 级保险箱，其次才用体力；保险箱不消耗体力，因此体力为零但存在已确认保险箱时仍可继续。
- 支持 1280×720 的 8 列、6 行棋盘，无选中项或任意棋子已选中的中途状态。入口只依据新截图重建当前棋盘，不继承上次的棋子、次数或返回栈。
- 主鱼缸、活动目录、帮助、任务、兑换、奖励弹窗不作为入口；缺少经过取证的导航门禁，故意不自动进入或退回。这是棋盘局部工作流，不接入日常收尾或巡检。
- 不获取体力，不点击加号，不长按生成，不购买，不删除、不提取资源、不兑换最终奖品。5 级保险箱的明确“生成新棋子”属于生成能力，不是贝币、鱼粮等资源提取；其它 Max 棋子不会因此获准点击。结束时保留在棋盘。
- 气泡棋子不能直接参与合成，默认点击详情中的「忽略」，不点击下方消耗开心宝的「戳破」。这一处理无需额外选项；确认气泡所在格变空后重新扫描，继续当前合成或使用已有体力模式。

## 实现契约

入口为 `ShoppingCarnivalTask`，调用 `agent/shopping_carnival.py` 的 `ShoppingCarnivalMergeAction`，由 `agent/main.py` 导入注册。无需新增依赖。

1. 每次操作前重新截屏；活动标题模板与绝对亮度同时确认，拒绝被帮助弹窗压暗的棋盘。只接受 1280×720。
2. 格中心为 `(305 + 99×列, 143 + 99×行)`，列 0～7、行 0～5。桃色空格与白色锁定底座分开判定；四角青色标记只表示选中，不代表可移动。
3. 逐项读取右侧名称、等级与合并说明；等级只识别实际数字行的数字区域，避免整行 OCR 把“等级11”吞成“等级1”。已选中的棋子直接读，不再点击，避免资源棋子的第二次点击触发提取。未选中时只点击一次，每半秒取新帧，最多六次确认该格四角选中标记，仍未选中则失败，不补点。识别不明确就失败，不能因缺说明跳过未知棋子后声称完成。
4. 精确的同名同级配对，来源必须可移动；优先把可移动棋子拖到同级锁定格，再考虑同类可移动格。最高等级不作为来源或目标。每次操作前再读双方详情，确认同名同级、合并说明、来源可移动以及目标选中且非空。全盘扫描前的旧图仅作为识别缓存线索，不再用旧像素差异否定当前 OCR 已确认的配对；资源绿色箭头闪烁也不参与配对身份判断。当前详情或目标选中态变化只允许两次重建计划，不执行拖拽或生成，再变化则失败。升级结果以目标新帧中的等级加一为正向证据，不再以像素差异代替实际等级。
5. 合成前至少留三格空位，预留奖励空间。一次 600 毫秒拖拽后等新帧，确认目标非空并读取详情，目标等级必须恰好加一才记成功。合成奖励可以立即落回来源格，不再要求来源格为空；成功后清除来源和目标的旧识别缓存，下轮重新识别新棋子。目标为空、等级不变或无法确认时仍失败，不重复拖拽。
6. 没有可合成对时，「只合成」正常结束；生成模式只判断零体力专用模板，不读取正数、不要求生成前后体力减一，也不因数字 OCR 置信度不足报错。无保险箱且确认体力为零时正常结束；至少四个空位、棋盘与生成器门禁通过且未命中零体力时，才单击体力生成器。生成后仍须确认空位减少一格才继续；无变化不连点。达到生成或操作上限属于未完成，返回 False。
7. 三十分钟、600 次操作双上限，等待阶段频繁检查停止。未知页面、OCR 不确定、空间不足或变化未确认记录 ERROR 并返回 False；任务无 `next` 或 `on_error`，不会把失败包装为成功。
8. 保险箱只有名称 `保险箱`、等级 5、正文同时含“点击生成新棋子”和“最高”时才作为生成器。不读取体力数字或比较体力变化；先按普通单击选中规则读取当前详情，再新帧确认已选中和至少四个空格后单击生成一次；不因它标 Max 或有手指图标就猜测其它棋子的用途。每半秒观察、最多六次，必须只有一个原空格新增不可移动棋子，且原有其它棋子未消失，才清空识别缓存回到合成循环；保险箱自身允许在耗尽后消失，但本次未取证耗尽行为。新棋子作为锁定目标，仍不能作为拖拽来源。未确认产出不补点、不改用体力继续掩盖失败。
