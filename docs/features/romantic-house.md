# 浪漫满屋祝福自动化 (RomanticHouseTask)

## 模块概述
浪漫满屋（RomanticHouseTask）是开心水族箱小助手的自动化日常任务之一，旨在自动寻访主鱼缸的珊瑚装饰，通过情侣鱼气泡进入“浪漫满屋”活动页，并在“热恋时刻”舞台中循环为情侣鱼点赞祝福，直到本日点赞值达到 `10/10` 满额后安全双级退出回主鱼缸。

---

## 核心设计原则（Anti-Pitfalls & Hard Rules）

1. **数值状态驱动（Value-Driven）**：
   - 任务唯一终态判定为**“本日获得点赞值：10/10”**；
   - 严禁以情侣鱼种类、名称、好友昵称、头像或排列次序作为完成或流转条件；
   - 严禁在代码或配置中硬编码任何情侣鱼名称。

2. **步骤可恢复架构（Deepest-First Recovery Contract）**：
   任务启动时通过 `RomanticHouseStartRouter` 动态识别当前所在界面深度：
   - **Stage 1 (最深态)**：已处于“热恋时刻”舞台（识别到点赞横幅 `10/10` 或舞台特征）-> 直接触发终态判定与退出；
   - **Stage 2 (中间态)**：已处于“浪漫满屋”主页（识别到左侧“热恋时刻”木牌）-> 直接点击进入舞台；
   - **Stage 3 (起始态)**：处于主鱼缸（识别到右下珊瑚装饰）-> 触发气泡并进入。

3. **入口固定位置点击与游鱼遮挡重试（2026-09-18 改造）**：
   - 主鱼缸里的鱼会游动，海藻/珊瑚与气泡都可能被临时遮挡；`Click` 的 `Action.Succeeded` 只代表点击发出，不代表真的进入页面；
   - 入口不再依赖 `浪漫满屋_珊瑚.png` / `浪漫满屋_气泡.png` 识别定位（模板文件保留，仅退出生产入口）；
   - `RomanticHouseInFishTank`：`主界面特征.png` 门禁确认主鱼缸后，固定位置点击海藻 `[842, 554, 126, 56]`；
   - `RomanticHouseWaitBubble`：`DirectHit` 固定位置点击气泡 `[878, 391, 71, 57]`；
   - 真正成功门禁仍是 `RomanticHouseInHomePage`（热恋时刻木牌）：命中则继续业务；未命中但主鱼缸门禁仍成立时自动重试整套入口（确认主鱼缸 → 海藻 → 气泡 → 验证主页），不设小重试上限，用户手动 Stop 正常停止；
   - 既不在主页也不在主鱼缸（动画/弹窗/未知）：经 `RomanticHouseTransientWait` 短暂等待后重走 `RomanticHouseStartRouter`，仍未知则任务安全失败；固定坐标点击只允许发生在已确认主鱼缸的入口流程内，绝不在未知页面盲点。

4. **防重复点击与已祝福跳过**：
   - 祝福按钮为粉色胶囊，点击后在 0.5s 内原地刷新为灰白胶囊“已祝福”；
   - 若当前情侣鱼已为“已祝福”，Pipeline 自动跳过并点击右侧箭头 `>` 切换至下一对情侣鱼。

5. **双级安全退出（Safe Dual-Exit）**：
   - 达到 `10/10` 后，点击右上角粉色小叉号退出“热恋时刻”舞台；
   - 再次点击右上角粉色小叉号退出“浪漫满屋”主页，回到主鱼缸，确保不干扰后续挂机任务。

## 历史事故复盘与经验教训

### 1. 关闭按钮半透明背景导致 0.70 阈值卡死 (2026-09-05)
- **现象**：实测点赞达到 10/10 后，任务卡在舞台页面不断循环等待，未能自动点击退出。
- **根因**：模板 `浪漫满屋_关闭.png` 截取自主页，而舞台页面的右上角背景带有半透明叠加层，实测匹配度为 `0.6236`。因原阈值配置为 `0.70`，导致 `0.6236 < 0.70` 判定失败。
- **修复**：将退出节点的匹配阈值下调至 `0.55`，经实测完美命中且具备高容错性。

### 2. MaaFramework on_error 假分支陷阱导致祝福死锁 (2026-09-06)
- **现象**：成功进入【热恋时刻】情侣祝福界面后，任务不点击【祝福】按钮，不执行【右箭头】切换，原地等待超时失败。
- **根因**：误将 `on_error` 当作 `if-else` 分支。在 MaaFramework 中，候选节点（如 `RomanticHouseCheckDone`）识别未命中时（点赞值未达 10/10），框架仅判定未命中本节点，**绝不会触发该节点的 `on_error`**，而是继续轮询 `next` 候选列表。原配置中 `RomanticHouseInHomePage.next` 仅包含 `RomanticHouseCheckDone`，导致下游 `RomanticHouseTryBless` 永远不可达。
- **修复**：
  1. 扁平化候选结构：将 `RomanticHouseCheckDone`、`RomanticHouseTryBless`、`RomanticHouseNextCouple` 并列作为 `next` 候选，按优先级自然回退；
  2. StartRouter 补全：将情侣舞台候选纳入 `RomanticHouseStartRouter.next`，实现舞台中途断点恢复；
  3. 死循环防御：为 `RomanticHouseNextCouple` 设定 `max_retry: 25` 与 `on_error: RomanticHouseExitStage` 熔断。

### 3. 关闭按钮模板偏位夜空空击与 DirectHit 假完成 (2026-09-06)
- **现象**：10/10 满额后，MFA 界面显示任务已完成，但模拟器实际画面停留在热恋时刻舞台，未退出到主页，未返回主鱼缸。
- **根因**：
  1. 模板偏位：历史模板 `浪漫满屋_关闭.png` 实际截取自活动主页右侧粉色樱花背景 `(1205, 50, 60, 60)`，并不包含爱心与叉号。在舞台深黑紫夜空背景下以 0.6236 伪命中后，随机点击点在 `(1215, 82)` 与 `(1249, 96)`（纯夜空背景），根本没有点击到爱心按钮 `(1197, 57)`；
  2. 盲目流转：`ExitStage` 盲走 `ExitHome`，再盲走 `RomanticHouseDone (DirectHit)`，全程无任何阶段状态感知（不校验是否回主页，不校验是否回鱼缸）。
- **修复**：
  1. 模板重制：截取以 `(1197, 57)` 为中心的完整粉心与叉号，使用 Alpha 通道剥离背景，实测置信度达 1.0000（舞台）与 0.9803（主页），阈值恢复至 0.85；
  2. 状态驱动闭环退出：`ExitStage` $\rightarrow$ 确认 `RomanticHouseCheckInHome`（热恋时刻木牌） $\rightarrow$ `ExitHome` $\rightarrow$ 确认 `RomanticHouseDone`（识别主鱼缸珊瑚），彻底杜绝无条件的 `DirectHit` 假完成。

### 4. 入口依赖珊瑚/气泡模板被游鱼遮挡导致入口失败 (2026-09-18)
- **现象**：鱼缸里的鱼会游动，识别到珊瑚后点击瞬间可能被鱼挡住，或气泡被遮挡导致模板不命中；`Click` 成功只代表点击发出，页面实际未进入，流程走失败路径。与开贝壳入口同源（见 `docs/features/open-shell.md`）。
- **根因**：入口第一步用 `浪漫满屋_珊瑚.png` 定位并要求模板可见才点击，第二步要求 `浪漫满屋_气泡.png` 命中，未命中再盲点旧坐标 `[874,387,71,65]`；入口位置本身固定，却被动态游鱼支配。
- **修复**：入口改为「主鱼缸门禁 + 固定位置点击」——`RomanticHouseInFishTank` 用 `主界面特征.png` 确认主鱼缸后固定点海藻 `[842,554,126,56]`，`RomanticHouseWaitBubble` 改 `DirectHit` 固定点气泡 `[878,391,71,57]`；以 `RomanticHouseInHomePage` 验证真正进入，未进入但仍在主鱼缸则自动重试整套入口（无小上限，Stop 正常停止）；未知页面经 `RomanticHouseTransientWait` 短暂等待重走 Router，仍未知安全失败，绝不盲点。`RomanticHouseDone` 的回缸确认同步改用 `主界面特征.png`（鱼缸 0.9747 命中，舞台/主页 0.44 左右 MISS，假完成防线更扎实），不再要求珊瑚可见；删除 `RomanticHouseClickBubbleFallback` 盲点节点，珊瑚/气泡模板文件保留但退出生产入口。测试 `dev/test_romantic_house_entry.py`（Case 1~5）与 `dev/test_romantic_house_flow.py`（情况 A/B/C，match_node 修正为 Maa 真实 BGR 匹配算法）全部通过；代码级验证完成，待实机复测。
