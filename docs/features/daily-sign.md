## 功能目标

签到窗口会在跨过零点后由游戏主动弹出，特惠礼包、活动页面、快报或升级弹窗也可能在任务运行期间出现。自动化任务不主动寻找入口，而是在所有标准 `1280×720` 游戏 Pipeline 状态转换检查点优先识别并处理这些页面。

## 用户截图契约

本功能采用用户手动截图模式，以下模板按用户说明直接接入，不重新截图或复核其内容：

- `活动页面_退出.png`：用户确认该模板表示活动页面已经弹出；在 `[0, 0, 136, 116]` 内识别，点击模板实际命中位置后返回鱼缸主页面；
- `签到_识别.png`：确认签到弹窗已经出现，只用于识别，不点击；
- `签到_点击.png`：下方「签到」二字，只在屏幕下半区 `[0, 400, 1280, 320]` 内匹配并点击实际命中位置；标题「签到寻宝」不在此 ROI 内。模板未命中时，再用 OCR `^签到$` 在同一 ROI 内点击文字。
- `签到_关闭.png`：领取动作已下发或 OCR 确认「已签到」后关闭页面，识别 ROI `[1000, 0, 220, 160]`；`DailySignCloseAction` 每次重新截图，正向确认签到标题仍在并匹配关闭按钮，只点击命中框与用户指定范围 `[1084,45,41,43]` 的交集中心（本次为 `(1104,66)`），最多三次。标题正向识别返回未命中才确认消失；调用失败不能当作消失。缺模板、范围无交集、触摸失败、截图失败或三次后仍未关闭均报 ERROR 并停止，禁止重新领取循环。
- `特惠礼包_识别.png`：确认特惠礼包弹窗已经出现，只用于识别；
- `特惠礼包_关闭.png`：特惠礼包关闭按钮，只通过模板匹配结果点击。
- 快报页面先在 `[635,23,226,162]` OCR 识别“快报”作为页面门禁；
- `快报页面_关闭.png`：门禁通过后在 `[1044,77,26,31]` 匹配并点击关闭按钮的实际命中位置。
- `升级弹窗_识别.png`：在 `[200,348,378,185]` 内确认升级弹窗已经出现，只用于页面门禁；
- 门禁通过后在 `[957,627,125,47]` OCR 识别“太好了”，点击 OCR 实际命中位置关闭弹窗。

没有识别失败后的固定坐标兜底；用户指定区域只用于约束当帧模板命中后的点击，不替代页面及关闭模板门禁。

## 状态分支

```text
任意 Pipeline 检查点
  └─ 识别到签到弹窗（标题「签到寻宝」，不点击）
       ├─ 下半区 OCR「已签到」：直接进入关闭分支，不重复领取
       └─ 下半区匹配「签到」或 OCR `^签到$`：点击领取
            ├─ 弹窗已自动消失：直接完成
            └─ 弹窗仍在：重新匹配关闭按钮并点击中心
                 ├─ 确认标题消失：完成
                 └─ 三次仍在 / 缺模板 / 触摸失败：ERROR + StopTask
       └─ [JumpBack] 返回原任务继续扫描
```

`GlobalDailySignClose` 和 `GlobalDailySignAutoClosed` 是并列分支，不要求领取后一定出现关闭按钮，也不把自动关闭视为错误。仅 OCR 确认「已签到」时可以跳过领取，否则必须先点弹窗下方「签到」。领取模板与 OCR 是入口同一 `next` 的候选，不能依赖候选 recognition miss 触发该候选的 `on_error`；领取候选均未命中由父节点 4 秒超时后安全停止。

特惠礼包流程为单一路径：识别 `特惠礼包_识别.png` → 识别并点击 `特惠礼包_关闭.png` → 回到鱼缸。用户已确认关闭后没有额外步骤。

活动页面流程为单节点路径：优先识别 `[0, 0, 136, 116]` 内的 `活动页面_退出.png` → 点击实际模板位置 → 等待返回鱼缸 → 通过 `[JumpBack]` 继续原任务。该处理不使用固定点击坐标。

快报流程为两段页面门禁：在 `[635,23,226,162]` OCR 命中“快报” → 在 `[1044,77,26,31]` 匹配 `快报页面_关闭.png` 并点击实际位置 → 通过 `[JumpBack]` 回到刚才的任务节点继续执行。未命中“快报”时绝不单独点击右上角关闭区域。

升级弹窗同样采用两段门禁：在 `[200,348,378,185]` 匹配 `升级弹窗_识别.png` → 在 `[957,627,125,47]` OCR 命中“太好了”并点击实际文字位置 → 通过 `[JumpBack]` 回到刚才的任务节点继续执行。未确认升级弹窗时绝不点击确认区域。

该通用模板不用于大章鱼开贝壳页面；开贝壳页必须先用 `开贝壳_识别.png` 确认页面本体，再用 `贝壳页面_返回.png` 识别并点击返回按钮。

## 全局接入边界

- 标准游戏流水线在已接入的状态转换检查点按顺序优先处理活动、签到、特惠礼包、快报和升级弹窗，关闭后恢复原节点。不是每一个 `next` 都是全局检查点：配置初始化、受局部页面门禁约束的恢复链、原子动作及主动活动存在明确例外，见下表。也不是仅检查任务入口：其它未登记为例外的非空 `next` 同样要求五个处理器优先；
- `features/mobile_ads.json` 与 `features/emulator_ads.json` 都会进入外部广告画面，分别使用手机 `1600×720` 和模拟器 `1280×720` 的独立资产；两者不接入游戏签到/活动等全局门禁，防止在广告内容中误识别、误点击；
- 收鱼挂机的无限循环同样接入，适合跨零点长时间运行；
- 正在执行中的单个原子动作不会被强行打断；如果弹窗恰好在该动作期间出现，会在动作结束后的下一个 Pipeline 检查点处理，避免后台并发点击和误触；
- 处理器只接管已弹出的签到页，不主动寻找入口；入口支持可领取、已签到与弹窗刚消失三种状态。
- `DailyRoutineTask` 主动执行酿月食香活动体力时，`DailyRoutineDispatcher` 先判定当前步骤，再决定是否调用意外活动页处理器；仅当当前步骤为 `ACTIVITY_ENERGY` 时，活动列表交由该子任务处理，避免刚进入列表就被全局处理器退出。其它日常步骤仍由原全局活动页处理器优先接管。
