# 全局弹窗：每日签到与特惠礼包

## 功能目标

签到窗口会在跨过零点后由游戏主动弹出，特惠礼包也可能在任务运行期间出现。自动化任务不主动寻找入口，而是在所有 Pipeline 状态转换检查点优先识别并处理这两类弹窗。

## 用户截图契约

本功能采用用户手动截图模式，以下模板按用户说明直接接入，不重新截图或复核其内容：

- `签到_识别.png`：确认签到弹窗已经出现，只用于识别；
- `签到_点击.png`：签到按钮，只通过模板匹配结果点击；
- `签到_关闭.png`：领取后仍保留弹窗时的关闭按钮，只通过模板匹配结果点击。
- `特惠礼包_识别.png`：确认特惠礼包弹窗已经出现，只用于识别；
- `特惠礼包_关闭.png`：特惠礼包关闭按钮，只通过模板匹配结果点击。

流程中没有固定坐标点击。

## 状态分支

```text
任意 Pipeline 检查点
  └─ 识别到签到弹窗
       └─ 识别并点击签到按钮
            ├─ 识别到关闭按钮：点击关闭
            └─ 签到弹窗已自动消失：直接完成
       └─ [JumpBack] 返回原任务继续扫描
```

`GlobalDailySignClose` 和 `GlobalDailySignAutoClosed` 是并列分支，不要求领取后一定出现关闭按钮，也不把自动关闭视为错误。

特惠礼包流程为单一路径：识别 `特惠礼包_识别.png` → 识别并点击 `特惠礼包_关闭.png` → 回到鱼缸。用户已确认关闭后没有额外步骤。

## 全局接入边界

- 所有现有非空 `next` 列表均把 `[JumpBack]GlobalDailySignPopup` 和 `[JumpBack]GlobalSpecialOfferPopup` 放在业务节点之前，因此弹窗会优先于正常后继节点处理；
- 收鱼挂机的无限循环同样接入，适合跨零点长时间运行；
- 正在执行中的单个原子动作不会被强行打断；如果弹窗恰好在该动作期间出现，会在动作结束后的下一个 Pipeline 检查点处理，避免后台并发点击和误触；
- 独立运行 `DailySignTask` 时，当前没有签到弹窗也会正常完成，不报错。

## 待实机验证

- [ ] 领取后弹窗自动关闭分支；
- [ ] 领取后需要点击右上角关闭按钮分支；
- [ ] 跨零点长时间挂机时，处理完成后原任务能够继续。
- [ ] 特惠礼包在各业务中途出现时能够关闭并回到鱼缸；关闭动作本身已由用户手动确认，但尚未完成 MFA 自动化实测。

用户当前无法确认领取后窗口究竟会自动关闭还是需要手动关闭，因此两条分支都必须长期保留，不能在未经实测的情况下删掉其中之一。

特惠礼包关闭后会回到鱼缸，可能丢失原业务页面。当前全局处理保证识别与关闭；各任务能否从该时点继续，取决于原任务当前节点的步骤可恢复能力，后续 MFA 测试应重点观察这一点。
