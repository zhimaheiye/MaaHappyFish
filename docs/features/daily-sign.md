# 全局页面处理：活动页面、每日签到与特惠礼包

## 功能目标

签到窗口会在跨过零点后由游戏主动弹出，特惠礼包或活动页面也可能在任务运行期间出现。自动化任务不主动寻找入口，而是在所有 Pipeline 状态转换检查点优先识别并处理这些页面。

## 用户截图契约

本功能采用用户手动截图模式，以下模板按用户说明直接接入，不重新截图或复核其内容：

- `活动页面_退出.png`：用户确认该模板表示活动页面已经弹出；在 `[0, 0, 136, 116]` 内识别，点击模板实际命中位置后返回鱼缸主页面；
- `签到_识别.png`：确认签到弹窗已经出现，只用于识别；
- `签到_点击.png`：签到按钮，只通过模板匹配结果点击；
- `签到_关闭.png`：领取后关闭签到页面的按钮；只在签到动作成功后识别，识别 ROI 为 `[1033, 0, 148, 140]`，并点击按钮中心小区域 `[1103, 63, 6, 6]`，避免框架随机点到模板边缘。
- `特惠礼包_识别.png`：确认特惠礼包弹窗已经出现，只用于识别；
- `特惠礼包_关闭.png`：特惠礼包关闭按钮，只通过模板匹配结果点击。

流程中没有固定坐标点击。

## 状态分支

```text
任意 Pipeline 检查点
  └─ 识别到签到弹窗
       └─ 识别并点击签到按钮
            ├─ 识别到关闭按钮：点击关闭
            └─ 签到弹窗已自动消失：直接完成
       └─ [JumpBack] 返回原任务继续扫描
```

`GlobalDailySignClose` 和 `GlobalDailySignAutoClosed` 是并列分支，不要求领取后一定出现关闭按钮，也不把自动关闭视为错误。关闭识别绝不能放到领取之前：只有一层签到页面，先关闭会漏签。

特惠礼包流程为单一路径：识别 `特惠礼包_识别.png` → 识别并点击 `特惠礼包_关闭.png` → 回到鱼缸。用户已确认关闭后没有额外步骤。

活动页面流程为单节点路径：优先识别 `[0, 0, 136, 116]` 内的 `活动页面_退出.png` → 点击实际模板位置 → 等待返回鱼缸 → 通过 `[JumpBack]` 继续原任务。该处理不使用固定点击坐标。

该通用模板不用于大章鱼开贝壳页面；开贝壳页必须先用 `开贝壳_识别.png` 确认页面本体，再用 `贝壳页面_返回.png` 识别并点击返回按钮。

## 全局接入边界

- 除“点击产物气泡后立即滑动收取”的原子链外，所有现有非空 `next` 列表均把 `[JumpBack]GlobalActivityPagePopup`、`[JumpBack]GlobalDailySignPopup` 和 `[JumpBack]GlobalSpecialOfferPopup` 放在业务节点之前，因此全局页面会优先于正常后继节点处理；原子链会在紧接着的下一个检查点处理活动页面，避免破坏双倍收取手势；
- 收鱼挂机的无限循环同样接入，适合跨零点长时间运行；
- 正在执行中的单个原子动作不会被强行打断；如果弹窗恰好在该动作期间出现，会在动作结束后的下一个 Pipeline 检查点处理，避免后台并发点击和误触；
- 独立运行 `DailySignTask` 时，当前没有签到弹窗也会正常完成，不报错。
