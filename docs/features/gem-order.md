# 宝石订单功能

## 功能目标

`GemOrderTask` 从主鱼缸进入宝石订单页面，依次处理当天的免费订单：当前订单可完成时点击“完成”，不可完成时点击“丢弃”；当页面进度达到 `10/10` 后退出并确认回到主鱼缸。

## 状态机

```text
GemOrderTask
  -> 已在订单页：GemOrderOnPage
  -> 仍在主鱼缸：GemOrderOpenEntry -> GemOrderOnPage
  -> 其他状态：GemOrderAbort

GemOrderRouter
  -> OCR 命中 10/10：GemOrderExit -> GemOrderVerifyTank
  -> 特殊订单对号：GemOrderComplete -> 重新确认订单页
  -> 普通订单对号：GemOrderComplete -> 重新确认订单页
  -> 两种对号均未命中且“丢弃”存在：GemOrderDiscard -> GemOrderConfirmDiscard -> 重新确认订单页
  -> 关键状态均未命中：GemOrderAbort
```

## 行为约束

- 启动时采用最深阶段优先：若已经在宝石订单页，则直接从当前订单继续，不强制返回鱼缸重进。
- `10/10` 是最高优先级终态；达到上限后不会再点击“完成”或“丢弃”。
- 特殊订单和普通订单的对号是状态门禁，不直接点击；任一模板命中后均复用同一个 OCR“完成”按钮。
- 只有两个可完成对号均未命中时，才允许点击订单页的第一次“丢弃”；随后必须在确认弹窗 `[603,460,85,32]` 再次 OCR 识别并点击“丢弃”。
- 每次“完成”或确认“丢弃”后必须重新识别 `宝石订单_识别.png`，确认页面仍正确再进入下一轮。
- 退出使用 `宝石订单_退出.png` 的真实匹配位置，最终以 `主界面特征.png` 确认回到鱼缸；页面或按钮门禁失败时立即停止，禁止固定坐标盲点。
- 所有可恢复节点优先接入活动页、签到、特惠礼包和快报四类全局弹窗处理，关闭后继续当前流程。

## 2026-09-13 丢弃确认 OCR 修复

- 实机日志显示确认按钮已被 OCR 定位为 `[607,460,67,31]`，完整落在原 ROI `[603,460,85,32]` 内，因此失败原因不是坐标偏移。
- OCR 文本稳定返回繁体首字的“丟弃”，旧正则 `^丢弃$` 因文字不一致将识别结果过滤，等待约 20 秒后进入安全停止。
- 订单页第一次丢弃与弹窗确认丢弃统一改为 `^[丢丟]弃$`，兼容简体“丢弃”和 OCR 结果“丟弃”；原 ROI 保持不变，避免无依据扩大点击范围。
- 本次修复完成代码级验证，确认弹窗实际点击与后续订单切换仍需 MFA 自然复测。
