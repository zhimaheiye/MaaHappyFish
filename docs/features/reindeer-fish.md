**最后更新**：2026-09-08  
**证据模式**：用户手动截图  
**实机状态**：已确认能够进入单按钮“一键收取”页面；单按钮与双按钮属于两种并列布局，当前识别优化后的完整领取返回仍待复测

## 功能范围

本功能仅作为 `DailyRoutineTask` 的可选子任务，默认不勾选。入口模板 `游乐园入口.png` 与 `驯鹿鱼_入口.png` 均由用户提供；本轮不使用 ADB/maa-mcp 复核图片。

```text
鱼缸
  -> 模板点击 游乐园入口.png
  -> 模板点击 驯鹿鱼_入口.png
  -> 页面状态路由
       ├─ 单按钮布局：中间 OCR“一键收取” [678,562,235,147]
       │    -> OCR“返回” [536,437,210,150]
       │    -> 通用返回
       └─ 双按钮布局：左侧 OCR“一键回礼” [480,562,232,143]
            （右侧“去送礼”暂不点击）
            -> 全屏 OCR“直接赠送” -> 点击 -> 通用返回
            └─ 未出现弹窗 -> 通用返回
  -> 模板确认回到鱼缸
  -> 推进日常收尾队列
```

## 安全与兼容边界

- 所有点击均由当前页面的模板或 OCR 命中触发，不使用固定坐标兜底。
- “直接赠送”按用户要求暂不限制 ROI；仅在点击“一键回礼”之后优先识别。
- 当前不点击右侧“去送礼”，也不猜测尚未提供的弹窗或空状态。
- 单按钮“一键收取”与双按钮“左侧一键回礼、右侧去送礼”均属于已收录状态；两个识别节点并列存在，不把一个 ROI 当成另一个 ROI 的修正或替换。若 OCR 未命中，只记录“未识别到可执行操作”，不再误报为“尚未收录”。真正未知页面仍安全停止。
- 2026-09-08 17:26 实机日志确认单按钮页 OCR 将“一键收取”识别为高置信度的“键收取”（0.997792）；识别关键词采用稳定子串 `键收取`，同时兼容完整文本与漏首字结果，ROI 保持 `[678,562,235,147]` 不变。
- 通用返回按钮采用 `docs/ui-conventions.md` 中的 OCR 契约：`expected: 返回`、`roi: [1,0,189,119]`。
