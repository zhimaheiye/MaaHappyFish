## 功能范围

本功能仅作为 `DailyRoutineTask` 的可选子任务，默认不勾选。入口模板 `游乐园入口.png` 与 `驯鹿鱼_入口.png` 均由用户提供；本轮不使用 ADB/maa-mcp 复核图片。

```text
鱼缸
  -> 模板点击 游乐园入口.png
  -> 模板点击 驯鹿鱼_入口.png
  -> 页面状态路由 (ReindeerFishStartRouter)
       ├─ 场景 A & C: 底部 OCR“一键收取” [480,562,440,143] (ReindeerFishCollectAll)
       │    -> ReindeerFishAfterCollectRouter (4000ms 稳定识别窗口)
       │         ├─ 奖励弹窗: OCR“返回” [536,437,210,150] (ReindeerFishRewardReturn) -> 重新进入 AfterCollectRouter
       │         ├─ 页面刷新出一键回礼: OCR“一键回礼” [545,611,121,45] (ReindeerFishReplyAll) -> 现有回礼业务链
       │         └─ 超时无弹窗/无回礼 (on_error): ReindeerFishAfterCollectNoReply -> 通用返回
       └─ 场景 B: 初始即无收取、只有回礼: 左侧 OCR“一键回礼” [545,611,121,45] (ReindeerFishReplyAll)
            -> ReindeerFishAfterReplyRouter
                 ├─ 全屏 OCR“直接赠送” -> 点击 -> 通用返回
                 └─ 未出现弹窗 -> 通用返回
  -> 模板确认回到鱼缸 (ReindeerFishVerifyTank)
  -> 推进日常收尾队列
```

## 安全与兼容边界

- 所有点击均由当前页面的模板或 OCR 命中触发，不使用固定坐标兜底。
- “直接赠送”按用户要求暂不限制 ROI；仅在点击“一键回礼”之后优先识别。
- 当前不点击右侧“去送礼”，也不猜测尚未提供的弹窗或空状态。
- 单按钮“一键收取”与双按钮“左侧一键回礼、右侧去送礼”均属于已收录状态；同时支持“初始即回礼”与“收取后刷新出回礼”场景。
- 2026-09-08 17:26 实机日志确认单按钮页 OCR 将“一键收取”识别为高置信度的“键收取”（0.997792）；识别关键词采用稳定子串 `键收取`，同时兼容完整文本与漏首字结果。
- 2026-09-12 13:04 报告确认礼物列表布局变化后，“键收取”的 OCR 框为 `[569,611,92,38]`，收取 ROI 已扩为 `[480,562,440,143]`，同时覆盖新旧按钮位置。
- 2026-09-14 实机测试确认“一键回礼”在收取后按钮精确 ROI 为 `[545, 611, 121, 45]`。通过 `ReindeerFishAfterCollectRouter` 设立 4000ms 窗口，关闭奖励弹窗后重新进入 Router，彻底避免第一帧未出现回礼而误判退出；超时后方判定无回礼并经由 `ReindeerFishAfterCollectNoReply` 安全返回。
- 通用返回按钮采用 `docs/ui-conventions.md` 中的 OCR 契约：`expected: 返回`、`roi: [1,0,189,119]`。
