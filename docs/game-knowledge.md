# 开心水族箱游戏数据与资源常识

本文记录会影响自动化设计、实机探索和测试授权的游戏常识。功能文档负责描述具体流程；当资源是否稀缺、能否消耗或某项机制是否可重复测试存在疑问时，以本文记录为准。

## 鱼食

### 廉价鱼食

- 当前自动化限定购买和投放的类别为“廉价鱼食”。
- 已知购买规格：每袋 30 粒，单价 400 金币；不使用贝币、钻石或现实付费。
- 廉价鱼食属于便宜、可大量补充的日常物资，购买目的本来就是喂鱼和给海星补充存粮。

### 开发与实机测试授权

只要在每次购买或投放前，视觉门禁已明确确认目标类别是“廉价鱼食”，Codex 可以为了完成鱼食购买、鱼食投放、海星喂食及其组合流程而进行充分、重复的 MuMu/MFA 实机测试，无需因为少量金币或鱼食消耗而暂停等待用户逐次确认。

测试目标优先级是尽量在代码交付前把完整流程跑通，使用户随后运行 MFA 时能够直接成功；不需要为了节省廉价鱼食而把验证缩减为只走一小段流程。

这项授权仍受以下边界约束：

1. 只能购买或投放已经识别确认为“廉价鱼食”的物品；不得改买活动鱼食、糖果、成长豆或其他商品。
2. 不得消耗贝币、钻石、现实货币、限次体力或其他稀缺资源；本授权不改变项目对付费点击的禁止。
3. 购买前仍须确认廉价鱼食名称、金币价格页面和购买按钮；投放前仍须确认海星/喂食页面及廉价鱼食袋，不允许使用识别失败后的固定坐标兜底。
4. 测试次数和购买数量可以按排查需要充分设置，但必须与当前功能验证成比例；不得留下停止任务后继续点击、无界长按或无限购买的后台操作。
5. 每轮动态测试应记录经过的关键页面、成功/失败节点和最终返回状态，便于判断是代码完成还是仍需用户 MFA 复测。

### 适用功能

- `BuyFishFoodTask`：购买廉价鱼食。
- `FeedStarfishStandalone`、`CollectFishTask`：给当前鱼缸海星补充鱼食。
- `PatrolTask`：在鱼缸管理页依次给多个鱼缸的海星补充鱼食。
- `ManateeTask` / `FriendGemTask` 海牛分支：只投放用户指定的现有鱼食，不执行购买；至少投喂 30 次，直到识别到刷新体力。
- 后续明确限定为廉价鱼食的购买或投放模块。

如果未来自动化支持其他鱼食类别，必须单独记录其价格、资源类型与测试授权；不得自动继承廉价鱼食的宽松测试规则。

## 空中金币/宝石产物的双倍奖励

- 鱼类产出的金币/宝石气泡被点击后，产物会从空中落下；若在空中主动收取，而不是等待落地后随时间自然拾取，奖励会加倍。
- 主鱼缸中直接匹配并点击 `金币气泡.png` 的收鱼/巡检流程，必须在每次点击后立刻执行一次鱼缸底部从左到右的水平滑动，再进行下一次气泡识别。
- 用户给定的安全滑动范围为 `[201, 630, 826, 66]`。当前固定手势为 `(221, 663) -> (1007, 663)`、持续 250ms，起点、终点和整条水平轨迹都位于该矩形内；不得超出范围，以免误触其他 UI。
- 当前适用入口共 4 个：`CollectFishTask` 1 个、`PatrolTask` 三个鱼缸各 1 个。`FriendGemTask` 明确不适用；海獭摸宝点击的是海獭本体，浪漫满屋点击的是活动气泡，也不属于该规则。

### 深海鱼缸专用鱼食

- 鱼缸 3 为深海鱼缸，当前自动化只在已经验证的选择喂食弹窗中投放第一格专用鱼食，不购买该鱼食。
- 深海鱼食不自动继承廉价鱼食的“可充分重复消耗”授权；实机验证只执行完成流程所需的最少投放。
- 当前鱼缸 3 对应第二个“乖海星”，但鱼缸与海星的对应关系可能变化，代码不得硬编码该位置或名称。

## 魔力召唤与宝石融合

- 高级魔力召唤点击确认后约十小时才能再次执行，属于稀缺测试机会；用户已明确保留当前一次机会用于巡检子功能验证，确认前仍须通过页面标题、黄色召唤按钮和绿色勾选三重视觉门禁。
- 宝石融合时长可配置，当前配置较短，可用于验证“融合中”“结果入库”“再次合成”状态；所有付费、钻石或未确认资源按钮仍不在授权范围内。
